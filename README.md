# 3D Theater

MMD 系のモデルを使って 3D アニメーションを作る、Windows 用のソフト。
何を作るかは [開発指示書](3D_Theater_開発資料一式/3D_Theater_開発指示書.md) にまとめてある。

## 今の状態（Phase 0〜5 の必須の内容が完了し、受入れチェック済み。Phase 5：切り替えの元に戻す・カメラの平行投影・プレビューで照明を選ぶ・セルフ影のキー・物理のモデルどうしの当たり・設定の画面の元に戻す・物理の床との当たり・映像効果のキーフレーム・表示・IK のキー・照明のキーフレーム・足した照明の影・レイトレーシングでの地面の影・レイトレーシングを速くする・GPU の時間を測る・レイトレーシングでの影・描画の待ちを減らす・レイトレーシングでの環境光の遮りと映り込み・画面の中の反射・床の映り込みのぼかし・レンダーパスの書き出し・プラグインの土台・プラグインからの編集・ツールバーと右クリックのメニューと状態表示・時間のかかる処理とファイルの形式・描画の SDK と連携の見本・編集の道具。Phase 4 まで完了：トゥーン描画と輪郭線・影・PNG と動画の書き出し・描画品質の設定・映像効果・イラスト風・拡張材質・照明の追加・床の映り込み・被写界深度・環境光の遮り・霧・柔らかな影・環境の画像・モーションブラー・書き出しの枠と見本）

受入れチェック（指示書 11 章）: 20 項目のうち 17 項目は自動の確かめで合格、3 項目（タイトルバーのドラッグと DPI の変更・視点のマウス操作・ドッキングのドラッグ）は手で確認。結果と手順は [受入れチェック](docs/受入れチェック.md)。確かめで見つけた 2 つの不具合（後で出した区画の写り方・物理を焼き直したときの揺れのずれ）を直した

ライブモード（計画は [設計判断記録](docs/設計判断記録.md) の 67 章。計画の 6 段は、すべて作った）で新しくできたこと:

- ライブモードの画面の作り直し（作業中。今は 2 段目まで。設計判断記録 78 章）: ドッキングとメニューバーをやめ、標準のタイトルバー（題名は「3D Theater」）で、カメラの視点のプレビュー 1 枚の上に、左のサイドバー（シーン・カメラ・照明・キャラクター・背景・設定。折り畳み式）と、右上の「トラッキング情報」「カメラ情報」を重ねる。右下でグリッドとボーンを切り替え、F11 で仮想フルスクリーン（タイトルバーと枠を消して画面いっぱい）にする。状態表示は出さず、エラーのときだけ左下に赤い字で出す。作り直すまでの間、メニューにあった物は、サイドバーの「設定」で開く設定画面に、メニューと同じ名前と並びで置いた（下の説明の「ライブのメニュー」「レンダリングのメニュー」などは、設定画面の同じ名前の項目）。シーンの一覧・プロパティ・モーフは、サイドバーの「今のパネル（作り直すまでの仮）」、トラッキングのパネルは「トラッキング情報」、キー操作のパネルは設定画面の「キー操作」にある
  - サイドバーの「キャラクター」「背景」「照明」（2 段目）: キャラクターは 1 体だけで、顔のトラッキングはキャラクターにだけ当てはめる（背景のモデルを自動では選ばない）。「読み込む...」で PMX を読み込み、いれば確かめてから入れ替える。外す・待機モーション・材質・物理のリセット、トラッキングの当てはめ方（鏡のように・目線・上半身・体をずらす・なめらかさ）、表情（モーフ）、位置・向きなどもここで操作する。背景は、キャラクター以外のモデルとアクセサリ（PMX はトラッキングしないサブキャラクター。「キャラクターにする」で入れ替えられる）。照明は、点光源・スポットライト・平行光を足す・外す（MMD の照明は外せない）・名前と色などを変える。一覧で選ぶとプレビューでも選んだことになり、ギズモで動かせる。ドラッグや起動の引数で読み込んだ PMX は、キャラクターがいなければキャラクターになる。前の版のライブのファイル（当てはめ先が「自動」）は、開くときに頭のボーンを持つ最初の PMX をキャラクターにする

- モードを分ける: 起動するときに、エディットモード（これまでのアプリ。キーフレームでモーションを付け、画像・動画に書き出す）とライブモード（部屋・小物・キャラクターを置き、配信などでその場で動かす）を選ぶ。保存するファイルは、エディットが `.3dtproj`、ライブが `.3dtlive`。ファイルを渡したとき（ダブルクリックで開いたときなど）は、選ばずにそのモードで起動する。ライブモードの窓には、モーション・キー・書き出しのメニュー、再生のボタン、タイムライン、グラフを出さない。ツールのメニュー「.3dtproj・.3dtlive をダブルクリックで開けるようにする」で、今の利用者にファイルの関連付けを登録する（外すこともできる）。ファイルのメニューで、もう一方のモードを別の窓で起動できる
- ライブの舞台（その 1）: ライブでは物理を実際の時間でいつも動かす（焼き込みは作らない）。ライブのメニュー「待機モーション・ポーズを読み込む」で、選んだモデルにモーションを当てはめると、モデルごとにそのモーションの長さで繰り返す（「待機モーションを外す」で外せる）。「配信用の画面を出す」で、シーンのカメラから見た絵だけ（格子・ボーン・ギズモ無し）を別の窓に出す。背景はグリーンバックなどのクロマキーの色、大きさは 1920 × 1080・1280 × 720・縦長・正方形から選び、ライブのファイルに保存する。OBS などのウィンドウキャプチャで「3D Theater 配信用の画面」を取り込む。ライブでは、モーフ欄・プロパティ欄のキーの操作と、シーンの一覧の映像効果・セルフ影・音声の行を出さない
- ライブの舞台（その 2）: MMD のアクセサリ（DirectX の .x。テキスト・バイナリ・圧縮）を、MMD と同じく 10 倍の大きさで読み込む（シーンのメニュー「アクセサリを追加」・ドラッグ）。.vac を読むと、書かれたボーン（ネギなら右手首）に付けて置く。プロパティ欄の「付ける先」で、マイクなどのモデルやアクセサリを、ほかのモデルのボーン（手など）に付けて一緒に動かせる（MMD の外部親。付けた瞬間の見た目のまま付き、元に戻せて、保存する）。エディットモードでも使える
- 顔のトラッキング（その 1）: ライブモードの「トラッキング」パネルで、カメラ（または確かめ用に、顔を撮った動画のファイル）を選んで開始すると、映像から顔の点（478 個）・表情の値（目を閉じる・口を開ける・笑顔など 52 個）・頭の向き（左右・上下・傾き）を読み、映像に顔の点を重ねて見せる（Google の MediaPipe の顔のモデルを、ONNX Runtime で CPU で動かす。1 枚 8 ms ほど）。スマホは、Android なら Windows の「モバイル デバイス」で、iPhone なら DroidCam などのアプリでカメラにできる
- 顔のトラッキング（その 2）: トラッキングを始めると、キャラクター（「頭」のボーンを持つモデル。パネルで選ぶこともできる）の頭・首・上半身・目線・まばたき・ウィンク・口（あいうえお・口角）・眉が、顔に合わせて動く。初めの 0.5 秒ほどの顔を「正面」として覚える（「正面にする」で覚え直す）。左右は映像と同じ向きに動く（あなたが右を向くと、キャラクターも自分の右へ。「鏡のように動かす」を入れると、鏡に映った自分のように動く）。顔の位置で上半身を傾ける、なめらかさの調節もできる。当てはめ方はライブのファイルに保存する。場面のボーンやモーフの値は書き換えず、待機モーションの上に顔の動きを重ねる
- スマホの顔のアプリから受け取る: トラッキングのパネルの映像で「スマホ」を選ぶと、スマホの顔のアプリが読んだ表情の値と頭の向きを Wi-Fi で受け取り、カメラと同じようにキャラクターへ当てはめる。iPhone の VTube Studio・Android の MeowFace は、スマホの IP をパネルに入れて「開始」（この PC はポート 21413 で受け取る）。iPhone の iFacialMocap・FaceMotion3D と、スマホから送る使い方の MeowFace は、パネルに出る PC の IP をスマホのアプリに入れる（ポート 49983・12345）。頭の向きが逆なら、パネルの「左右を逆に」などで直す。初めて受け取るときは、Windows のファイアウォールの確認で「アクセスを許可する」（プライベート ネットワーク）を選ぶ
- キー操作: ライブモードの「キー操作」パネルで、キーごとに動かすもの（表情のプリセット・小物の表示・モーフ 1 つ・トラッキングの開始と停止・「正面にする」・仮想カメラの入と切）と押し方（押すたびに入・切 / 押している間だけ）を決める。ほかのアプリ（ゲーム・配信ソフトなど）を使っている間も効き、そのキーは使っているアプリに渡さない（Ctrl・Alt・Shift と組み合わせるのを勧める）。表情は 0.2 秒でなめらかに出し入れし、トラッキングより優先する（目を閉じる表情の間はまばたきを止め、口と首はトラッキングのまま）。小物の表示は、その場だけ入れ替える（保存しない）。「試す」で動きを確かめられる。キーの決まりはライブのファイルに保存する
- 仮想カメラ（Windows 11）: ライブのメニューの「仮想カメラを使う」を入れると、Zoom・Discord・Teams・OBS・ブラウザーなどのカメラの一覧に「3D Theater (Windows 仮想カメラ)」が出て、配信用の画面と同じ絵（大きさ・背景の色も。1 秒に 30 枚）を送る。入れている間だけ出て、切る・アプリを閉じると消える。初めて入れるときだけ、カメラの元（部品）を Windows に登録するので、管理者の確認が出る（DLL は `C:\Program Files\3D Theater\VirtualCamera` に置く。ツールのメニューの「仮想カメラの登録を外す...」で外せる。アプリを新しくしたときは登録し直す）。Windows 10 では、OBS に「ウィンドウキャプチャ」で「3D Theater 配信用の画面」を足し、フィルターの「クロマキー」で背景の色を抜いて「仮想カメラ開始」を押すと、代わりにできる
- 速さのログ: ライブモードでは、1 分ごとに、描画・顔のトラッキング・仮想カメラの速さ（回/秒・1 回の時間・つかえ）と、重さ（CPU・メモリ・GPU のメモリ・電源）をログに書く。トラッキングを止めたとき・閉じたときには、まとめ（平均・最大・メモリの増え方・電池の減り方）を書く。起動したときには、ARM64 の PC で x64 の版をまねて動かしているかも書く。ほかの PC で確かめてもらったとき、「ログを集める」だけで速さとメモリの様子が分かる。このログで、仮想カメラが 1 秒に 25 枚ほどしか描いていなかった（画面の更新が 1 秒に 75 回のとき）ことが分かり、30 枚に直した

Phase 5 で新しくできたこと:

- 切り替えの元に戻す: 物理演算・物理の床との当たり・物理のモデルどうしの当たりの ON / OFF、ループ再生、終わりのフレームの変更を、Ctrl+Z で元に戻せる。モーション・音声の読み込みで伸ばした終わりのフレームは、読み込みと同じ 1 回の元に戻すで戻る。数の欄に入力の焦点があるまま元に戻すと、欄が古い数で上書きしてしまう不具合を直した
- カメラの平行投影（プロパティ欄のカメラの「平行投影（パース OFF）」）: MMD の「パース OFF」と同じく、遠近の無い写し方にする。写る大きさは注視点までの距離で決まり（距離 45 で縦に 25）、視野角は使わない。キーに入り、次のキーまで切り替わらない。MMD のカメラのモーション（VMD）のパース OFF のキーも、そのまま平行投影で写す（霧と環境の画像の背景は、平行投影ではかからない）
- プレビューで照明を選ぶ: 足した照明の目印（点光源の球・スポットライトの円すい・平行光の矢印）の近くをクリックすると、その照明を選ぶ（Ctrl で足す・外す）。目印はモデルより手前に描くので、モデルに重なっていても照明が選ばれる
- セルフ影のキー（シーン一覧の「セルフ影」）: MMD と同じく、セルフシャドウを使うかをキーで切り替える（次のキーまで変えない）。MMD のカメラ・照明のモーション（VMD）のセルフ影のキーを読み込んで使い、書き出しにも入れる（モード 2 はモード 1 と同じに描き、影範囲は使わずに書き戻す）
- 物理のモデルどうしの当たり（モデルのメニュー「物理をモデルどうしで当てる」。初期値は ON）: 複数のモデルを置いたとき、髪・スカートなど物理で動く部分が、ほかのモデルの体（ボーンに合わせて動く剛体）をすり抜けない。当たるかどうかは PMX の剛体のグループの決まり（MMD と同じ）。ほかのモデルの髪どうしは当たらない。焼き込みでも同じ結果になる
- 設定の画面の元に戻す: 映像効果・霧・影・イラスト風・床の映り込み・環境の画像の画面で変えた値を、Ctrl+Z で元に戻せる（画面を開いてから閉じるまでが 1 つの操作）。セルフシャドウ・地面の影の切り替えも 1 回ずつ戻せる。映像効果のキーと未登録の印も一緒に戻る
- 物理の床との当たり（モデルのメニュー「物理を床に当てる」。初期値は ON）: 髪・スカートなど物理で動く部分が、床（高さ 0）をすり抜けずに床の上で止まる。モデルを動かしたり傾けたりして置いても、シーンの床に当たる。プロジェクトに保存する
- 映像効果のキーフレーム（シーン一覧の「映像効果」）: 色調補正・ブルーム・周辺減光・被写界深度・霧の値を、キーで時間とともに変えられる（値は「映像効果...」「霧...」で変え、映像効果の行を選んで「キーを登録」。未登録の変更・自動キー・キーの編集・グラフ・保存はカメラと同じ）。使うか（ON / OFF）はキーで動かさない。「新しいプロジェクト」でカメラ・照明のキーも消えるように直した
- 表示・IK のキー（シーン一覧のモデルのいちばん上の「表示・IK」）: MMD と同じく、モデルの表示と IK ボーンごとの「IK を使う」をキーで切り替える（次のキーまで変えない）。IK を切った所では、ひざなどはキーの回転のまま。MMD のモーション（VMD）の表示・IK のキー（IK を切る・モデルを隠す）を読み込んで使い、書き出しにも入れる
- 照明のキーフレーム: MMD の照明と足した照明の位置・回転・色・明るさ・届く距離・広がり・ぼかしを、カメラと同じようにキーで動かせる（照明を選んで「キーを登録」。未登録の変更・自動キー・キーの編集・グラフ・保存もカメラと同じ）。カメラ・照明用のモーション（VMD）の照明のキーは MMD の照明に当てはまり、「カメラ・照明のモーションを書き出す」で照明のキーも書き出す
- 足した照明の影（プロパティ欄の「影を落とす（影をレイトレーシングで求めるとき）」）: 「影の設定...」でセルフシャドウを使い、「影をレイトレーシングで求める」にしたとき、足した照明（点光源・スポットライト・平行光）もモデルに影を落とす。くっきりした影。照明 1 つにつき少し重くなる（本物の GPU で約 1 ms）
- レイトレーシングでの地面の影（「影の設定...」の「影をレイトレーシングで求める」が、セルフシャドウと地面の影の両方にかかるようになった）: 床の点から照明へ光線を出して、地面の影を落とす物に当たるかを調べる。髪の透けた所は影を落とさない。やわらかさもかかる
- レイトレーシングを速くした: レイトレーシングの影が 3 倍ほど速くなった（ふつうのモデルの描画で、隠れた面のピクセルシェーダーを奥行きで省けるようにした）。やわらかい影は影の境目だけ光線を増やす。光線の数は描画品質で変わる（プレビュー: 軽い 4・ふつう 8・きれい 12、書き出し 16）。描き上がる絵は変わらない
- GPU の時間を測る: 状態表示の「描画 N 回/秒・X ms」にマウスを乗せると、GPU が描くのに掛けた時間（全区画の合計）も出る。重い効果の目安（RTX 4060 Ti・プレビュー 2 つ）: 効果なし 1.9 ms、レイトレーシングでの影 6.2 ms（やわらかさ 0.5 で 10.5 ms）、レイトレーシングでの環境光の遮り 5.9 ms、画面の中の反射 + レイトレーシング 4.2 ms
- レイトレーシングでの影（「影の設定...」の「影をレイトレーシングで求める」）: セルフシャドウを、照明から見た奥行きの画像の代わりに、影を受ける面から照明へ出した光線で求める。奥行きの画像の細かさによらず、影の縁がくっきり正確になる（重い）。やわらかさもかかる。地面の影は変わらない。プロジェクトに保存する
- 描画の待ちを減らした: プレビューは、GPU の完了を待たずに次の絵を描き、描き終えた絵を次の画面更新で出す（表示は 1 回分遅れる）。レイトレーシングの効果を使っても、UI スレッドの 1 回の描画は 11 ms ほどから 3 ms ほどになった（RTX 4060 Ti・プレビュー 2 つ）
- レイトレーシングでの環境光の遮り（「映像効果...」の「環境光の遮り」の中の「レイトレーシングで求める」）: 画面の奥行きの代わりに、面から出した光線をモデルの三角形に当てて遮りを求める。画面の外・物の裏の物も遮り、物の縁の奥が暗くにじむことも無い。重い（RTX 4060 Ti・プレビュー 2 つで、GPU の時間が 4 ms ほど増えた）。プロジェクトに保存する
- レイトレーシングでの映り込み（「映像効果...」の「画面の中の反射」の中の「レイトレーシングで、画面に映っていない物も映す」）: 画面の中の反射で見つからない所（画面の外・物の裏・カメラの方へ戻る向き）を、光線をモデルの三角形に当てて探して映す。当たった物の色は簡単な計算（影・輪郭線は付かない）。重い（RTX 4060 Ti・プレビュー 2 つで、1 回の描画が 5 ms ほど増えた）。プロジェクトに保存する
- 画面の中の反射（「映像効果...」の「画面の中の反射」）: 材質の設定で PBR にした、つやのある材質（磨いた床・金属の飾りなど）に、画面に映っているほかの物を映す（強さ・探す距離）。画面の外・物の裏は、レイトレーシングを使わなければ今までどおり環境の映り込み。すべての視点と書き出しにかかり、プロジェクトに保存する

- 床の映り込みのぼかし（「床の映り込み...」の「ぼかし」）: つやのある床のように、床に接する所はくっきり、床から深い所ほどぼやけて映す。0 なら今までどおりのくっきりの鏡。プレビューと書き出しにかかり、プロジェクトに保存する

- レンダーパスの書き出し（書き出しの画面の「パス」）: 合成用に、普通の絵と一緒に、アルファ・奥行き（16 ビット）・法線・物の ID・材質の ID・影・発光を別の PNG で書き出す（静止画と連番）。奥行き・法線・ID・影・発光はなめらかにしない（縁で値が混ざらないように）。奥行きの範囲と、ID の色と物・材質の対応表を 名前_passes.json に書く

- プラグイン（メニュー「プラグイン」）: C# の DLL で、メニューのコマンド（ショートカットも）とドッキングパネルを足せる。「プラグインの管理...」で一覧・状態・問題の記録を見て、有効・無効を切り替える（初めて見つけたものは無効。無効にするとメニューとパネルがすぐに外れる）。プラグインのエラーではアプリを止めず、始める途中でアプリが落ちたら次の起動でそのプラグインを無効にする。Shift を押しながら起動すると安全モード（プラグインを始めない）。見本の「サンプル: シーンの情報」（今のフレーム・モデル・選択を出すパネルと、2 つのコマンド）を同梱した。作り方は [プラグインの作り方](docs/プラグインの作り方.md)
- プラグインからの編集（SDK 1.1）: プラグインがボーン・モーフの値とキーを読み・変えられる。プラグインの編集はアプリの「元に戻す」の 1 つの操作になり（編集のメニューに「元に戻す: 〜」と出る）、途中でエラーが起きたら始める前に戻す。サンプルに「まばたきを入れる」（選んだモデルにまばたきのキーを 3 つ打つ。1 回の Ctrl+Z で消せる）を足した
- プラグインのボタンと欄（SDK 1.2）: プラグインのコマンドを、ツールバーのボタンと、プレビュー・シーンの一覧の右クリックのメニューに出せる。状態表示に文字の欄も足せる。シーンの一覧に右クリックのメニュー（名前を変える。プラグインの項目）を足した
- プラグインの処理とファイルの形式（SDK 1.3）: プラグインの時間のかかる処理に、進み具合の窓と「取り消す」を出す。プラグインがファイルの形式を足すと、ファイルのメニューの「読み込む（プラグインの形式）」「書き出す（プラグインの形式）」に出て、ドラッグでも読み込める。書き出しは一時ファイルに書いてから置き換える（失敗・取り消しでも元のファイルを壊さない）。サンプルに「キーの CSV」（選んだモデルのキーの読み書き）と、時間のかかる処理の見本を足した
- 描画の SDK と連携の見本（SDK 1.4）: プラグインが、書き出しと同じ描き方で今のフレームを絵（画素と PNG）にできる。サンプルに「今のフレームを画像としてコピー（透明な背景）」（Ctrl+Alt+C。透過 PNG と白い背景の画像の 2 つの形でクリップボードへ。ほかのアプリに貼り付けられる）を足した。契約の DLL の隣に、説明の XML（API 文書）を出すようにした
- 編集の道具（SDK 1.5）: プラグインが、プレビューの左ボタンのドラッグで使う道具を足せる（ツールバーの押したままになるボタン）。ドラッグ 1 回の編集はアプリが 1 つの「元に戻す」にまとめ、Esc・右クリックで戻す。選んでいる間はギズモを出さない。サンプルに「センターを床の上で動かす」を足した。これで指示書 7.2 の拡張点に、どれも最初の版ができた

Phase 4 でできたこと:

- 書き出しの枠と見本: カメラ視点の区画に、書き出しの大きさの枠を出す（枠の中は書き出しと同じ写り方。枠の外は暗く）。書き出しの画面の「見本を描く」で、今の設定の書き出しを 1 枚描いて見られる。プレビューと書き出しの違いは [設計判断記録](docs/設計判断記録.md) の 38 章の一覧にまとめた
- モーションブラー（書き出しの画面の「動き」）: 1 フレームの間を何回かに分けて描いて重ね、動いている物とカメラの動きをぶらす（ぶれの長さ・分ける数）。物理も前後のフレームを補間してぶらす。隣り合うフレームのキー（カメラの場面の切り替え）は混ぜない。書き出しにだけかかる
- 環境の画像（レンダリングのメニュー「環境の画像...」）: 全方向の景色の HDR 画像（HDRI。Radiance の .hdr）で、拡張材質の PBR の材質を照らし、景色を映し込ませる（明るさ・回転）。背景にも表示できる（固定の視点と透明な背景の書き出しを除く）。トゥーンの材質は今までどおり。画像の場所はプロジェクトのフォルダーから見た場所でも保存する
- 柔らかな影（レンダリングのメニュー「影の設定...」）: 影を落とす物と受ける面が離れているほど、影の境目をぼかす（足元の床の影はくっきり、頭や腕の影ほどぼける）。セルフシャドウと地面の影の両方にかかる。地面の影の濃さも変えられる。0 なら今までどおりの MMD と同じ影。プロジェクトに保存する
- 霧（レンダリングのメニュー「霧...」）: 遠くの物ほど霧の色に溶けこませる（色・始まる距離・見通せる距離）。地面の近くほど濃くする霧にもできる。背景が色なら背景も霧の色になり、透明な背景の書き出しは透明のまま。カメラ視点・自由視点と書き出しにかかり、プロジェクトに保存する
- 環境光の遮り（レンダリングのメニュー「映像効果...」）: 物の隙間や接する所（わきの下・脚の内側・あごの下・髪の下など）を暗くして、形の奥行きを見せる（強さ・広がり）。すべての視点と書き出しにかかり、プロジェクトに保存する
- 被写界深度（レンダリングのメニュー「映像効果...」）: ピントの前後をぼかす（ピントの距離・ピントの合う幅・ぼけの大きさ）。初期値ではカメラの注視点にピントを合わせるので、カメラのモーションで寄ったり引いたりしてもついて行く。カメラ視点の区画と書き出しにだけかかり、プロジェクトに保存する
- 床の映り込み（レンダリングのメニュー）: 高さ 0 の床に、モデルを鏡のように映す（濃さ・消えるまでの距離）。照明と影も映した向きで当てるので、鏡に映ったのと同じ見え方。書き出しにもかかり、プロジェクトに保存する
- 照明の追加（シーンのメニュー）: 点光源・スポットライト・平行光を足し、色・明るさ・届く距離・広がりを変える。プレビューに目印の線が出る（書き出しには映らない）。足す・外すは元に戻せ、プロジェクトに保存する。MMD の照明にも色を付けられる。影をレイトレーシングで求めるときは、足した照明も影を落とす（照明ごとに選べる）
- 拡張材質（モデルのメニュー「材質の設定...」）: 材質ごとに、PBR（色合い・金属らしさ・粗さで光を返す）や発光（ブルームで光らせられる）で上書きする。PMX の材質とテクスチャは書き換えず、プロジェクトに保存する。元に戻せる
- イラスト風（レンダリングのメニュー）: 線画（奥行きの段差と面の折れ目に線を引く。太さ・濃さ・細かさ・色）、塗り（明るさの段階を減らす）、影の色（暗い所を選んだ色合いに寄せる）、紙の質感。プレビューと書き出しの両方にかかり、プロジェクトに保存する
- 映像効果（レンダリングのメニュー）: 色調補正（明るさ・コントラスト・彩度・色温度）、ブルーム（明るい所が周りへにじむ光）、周辺減光（四隅を暗くする）。プレビューと書き出しの両方にかかり、プロジェクトに保存する。背景・格子・ボーン・ギズモには色調補正とブルームはかからない
- 描画品質の設定（レンダリングのメニュー）: プレビューの品質を「軽い・ふつう・きれい」から選ぶ。ふつう以上は、線や輪郭のギザギザを GPU の機能（MSAA）で減らし、きれいは影も細かくする。書き出しは、いつも高い品質（4 倍のなめらかさ・細かい影）で描く

- 動画の書き出し（レンダリングのメニュー）: シーンのカメラから見た絵を MP4（H.264・AAC）で書き出す。フレームの範囲・大きさ・なめらかにする・背景の色・画質（標準・高画質）を選べ、シーンの音声も入れられる。Windows に入っている部品で書く（GPU の符号化があれば使う）。途中でやめると、書きかけは残さない

- PNG の書き出し（レンダリングのメニュー）: シーンのカメラから見た絵を、静止画か連番（名前_0000.png …）で書き出す。大きさ、なめらかにする（2 倍で描いて縮める）、背景の透明（透過 PNG）か色を選べる。格子・ボーン・ギズモなどは映らない。進み具合を出し、途中でやめられる
- 固定の視点（正面・側面・上面・下面）では、格子をモデルの後ろに描く

- 影: セルフシャドウ（モデルに落ちる影。受ける材質はトゥーンの影の色で描く、MMD と同じ描き方）と、地面の影（高さ 0 の床に落ちる半透明の黒の影）。レンダリングのメニューで ON / OFF でき、プロジェクトに保存する

- トゥーン描画: MMD と同じ色の計算（照明の色 × 拡散色 + 環境色、テクスチャ、スフィアの掛ける・足す、トゥーンの影、反射光）。共有トゥーン（toon01〜10）は、MMD のフォルダが見つかればその画像を、無ければ自前の画像を使う
- 輪郭線: 材質のエッジの色・太さと頂点の倍率で、モデルの外側に線を描く（材質モーフで色・太さも変わる）
- 照明: シーンの照明の項目の向き・色・明るさで照らす（新しいシーンは MMD の初期の向き）。照明を隠すと照明なし

- タイムラインの最小構成（目盛り・再生位置・再生/停止・1 フレーム移動・ループ・24/30/60 fps）
- プレビュー・シーン一覧・タイムライン・プロパティの選択の連動と、全プレビューが同じフレームを表示すること
- ログのパネル

まだできていないこと（「予定」と書いたメニューやボタンは押せない）:

- ギズモの拡大
- PMD（古い形式）の読み込み（後日）
- 透明な動画、プラグイン（Phase 5）
- 操作感度・ショートカットの設定画面、区画の境目のドラッグでの大きさ変更

モデルを読み込めるまでは、確認用の立方体で表示と操作を確かめる（再生位置に合わせて回る）。

## 必要なもの

- Windows 11（x64）
- Visual Studio 2026（Community 可）に次の 2 つを入れたもの
  - 「C++ によるデスクトップ開発」
  - 「.NET デスクトップ開発」
- .NET 10 SDK（Visual Studio と一緒に入る）

## ビルドとテスト

PowerShell でこのフォルダーを開いて実行する。

```powershell
.\build.ps1
```

- `-Configuration Release` で Release ビルド
- `-SkipTests` でテストを飛ばす
- `-Run` でビルドのあとアプリを起動する

スクリプトの実行が止められる場合は次のようにする。

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

### 確かめ用の zip（ほかの PC で動かす）

```powershell
.\package.ps1
```

- `artifacts\package\3DTheater-確かめ用-版-日付.zip` ができる（80 MB ほど）。ほかの PC（Windows 10 / 11 の 64 ビット）で、展開するだけで動く
  - .NET と Visual C++ の実行時ライブラリを中に入れてある（相手の PC に入れなくてよい）
- 中に、カメラの顔のトラッキングの「確かめの手順.txt」と、ログと PC の様子を 1 つの zip にまとめる「ログを集める.cmd」が入っている（ライブモードのログには、1 分ごとの速さと重さが入る。速さの行だけを抜き出した speed.txt も入れる）
- 「Claude への指示書.md」（zip の中と隣）: 相手の PC の Claude が読んで、コマンドだけで確かめを進める（`--track-camera`・`--exit-after` で起動し、コンセントと電池で 5 分ずつ動かし、結果とメモを受け渡しのフォルダーに置く）
- テストは流さないので、先に `.\build.ps1` で流しておく
- 署名していないので、相手の PC では「Windows によって PC が保護されました」と出る（「詳細情報」→「実行」）

Visual Studio で開く場合は `3DTheater.slnx` を開き、`3DTheater.App` をスタートアップにして実行する。
C++ のコードも続けてデバッグできるよう設定してある。

> C++ のプロジェクトを含むため、`dotnet build` ではビルドできない。`build.ps1` か Visual Studio を使う。
> 最初のビルドでは物理演算の Bullet（`external/bullet3`）もビルドするため、30 秒ほど長くかかる。

## 起動

```text
src\3DTheater.App\bin\x64\Debug\net10.0-windows\3DTheater.exe
```

何も渡さずに起動すると、エディットモードとライブモードのどちらで始めるかを選ぶ画面が出る（前回のモードを初めに選んでいる。「ファイルを開く...」で、どちらのモードのファイルも開ける）。

| オプション | 意味 |
|---|---|
| `--warp` | GPU を使わないソフトウェア描画で起動する（診断用） |
| `--debug-layer` | Release でも Direct3D の検査機能を使う（Debug では常に使う） |
| `--safe-mode`（Shift を押しながらの起動でも同じ） | 安全モード: 有効なプラグインも始めずに起動する（プラグインのせいで起動できないとき） |
| `--edit` / `--live` | モードを選ぶ画面を出さずに、エディットモード / ライブモードで起動する |
| PMX・.x・.vac のパス | 起動したあとに、そのモデル・アクセサリを読み込む（いくつでも並べられる） |
| VMD / VPD ファイルのパス | モデルを読み込んだ後に、そのモーション・ポーズを当てはめる |
| プロジェクト（.3dtproj）・ライブ（.3dtlive）のパス | そのモードで起動して開く（`--edit` / `--live` と食い違うときはファイルを優先する） |
| `--track-camera` / `--track-camera=名前の一部` | 確かめ用: ライブモードで、起動したらカメラで顔のトラッキングを始める（名前を渡すと、名前にそれを含むカメラ） |
| `--exit-after=秒` | 確かめ用: 起動してからその秒数（10 秒〜1 日）で、保存を尋ねずに閉じる（速さのまとめはログに書く） |

GPU での初期化に失敗したときは、自動でソフトウェア描画に切り替えて起動する。
GPU の面を WPF と共有できない環境では、描いた絵を読み出して表示する方式に自動で切り替える（状態表示に「読み出し方式」と出る）。

## 操作

| 操作 | 動き |
|---|---|
| 中ボタンでドラッグ | 視点を回す（固定視点からは自由視点へ移る） |
| Shift + 中ボタンでドラッグ | 視点を平行に動かす |
| ホイール | 拡大・縮小 |
| 左クリック | 選ぶ（Ctrl で追加・解除）。ボーンの線の近くならボーンを、足した照明の目印の近くなら照明を選ぶ |
| ダブルクリック / Num . | 選んだ物に合わせる |
| 右クリック | 視点のメニュー |
| シーンの一覧で右クリック | その行を選んで、名前の変更とプラグインの項目のメニュー |
| Num1 / Ctrl+Num1 | 正面 / 背面 |
| Num3 / Ctrl+Num3 | 右側面 / 左側面（Blender と同じ向き） |
| Num7 / Ctrl+Num7 | 上面 / 下面 |
| Num0 / Num5 | カメラ視点 / 透視と平行の切り替え |
| Space | 再生・一時停止（エディットモード） |
| ← / → | 1 フレーム移動（エディットモード） |
| Home / End | 先頭 / 末尾（エディットモード。プレビューの上では Home = 視点を初期状態に） |
| Ctrl+A / Esc | すべて選択 / 選択を解除 |
| Ctrl+N / Ctrl+O | 新しいプロジェクト / プロジェクトを開く |
| Ctrl+S / Ctrl+Shift+S | 保存 / 名前を付けて保存 |
| Ctrl+I | モデル（PMX）を読み込む（ウィンドウへのドラッグでも読み込める） |
| I | 選んだボーン・モーフを今のフレームのキーにする（エディットモード） |
| ギズモの取っ手を左ドラッグ | 動かす・回す（Ctrl でスナップ、ドラッグ中の右クリック / Esc で取り消し） |
| Q / W / E | 道具: 選択 / 移動 / 回転（Blender 方式に切り替わる） |
| Delete（キーを選んでいないとき） | 選んだモデルをシーンから外す（Ctrl+Z で戻せる） |
| Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） | 元に戻す / やり直し |
| Delete / Ctrl+C / Ctrl+V | タイムラインで選んだキーを削除 / コピー / 今のフレームに貼り付け |

タイムラインでは、キーをクリックで選び（Ctrl で追加・解除）、帯の空いている所からのドラッグで範囲選択、選んだキーのドラッグで移動（Ctrl を押しながらで複製）、右クリックで補間などのメニュー。再生位置は上の目盛りのドラッグか、帯の空いている所のクリックで動かす。

## 設定とログの置き場所

| 内容 | 場所 |
|---|---|
| レイアウト・プレビューの分け方・ウィンドウの位置と最大化（設定などの画面の位置も）・ギズモ・描画品質・書き出しの設定・前回のモード | `%APPDATA%\3DTheater\UserSettings\`（並びはエディットが `layout.xml`、ライブが `layout_live.xml`） |
| ファイルの関連付け（登録したときだけ） | `HKEY_CURRENT_USER\Software\Classes` の `.3dtproj`・`.3dtlive`・`3DTheater.Project`・`3DTheater.LiveProject` |
| ログ | `%LOCALAPPDATA%\3DTheater\Logs\`（メニュー「ヘルプ → ログフォルダーを開く」。同じ日に 2 つ目の 3D Theater を起動すると、`_2` の付いたファイルに書く） |
| 自動保存 | `%LOCALAPPDATA%\3DTheater\AutoSave\`（保存せずに終わったとき、次に起動すると復旧するか尋ねる） |
| プラグインの有効・無効と、プラグインごとの設定 | `%APPDATA%\3DTheater\UserSettings\settings.json` の `Plugins` |
| プラグイン（利用者が入れるもの） | `%APPDATA%\3DTheater\Plugins\`（アプリと一緒に配るものは、アプリのフォルダーの `Plugins\`） |

レイアウトがおかしくなったときは、ツールバーの「初期配置」を押すか、`UserSettings` フォルダーを消して起動し直す。
