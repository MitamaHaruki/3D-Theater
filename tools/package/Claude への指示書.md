# 3D Theater の確かめ（ノートパソコンの Claude への指示書）

この指示書は、利用者のノートパソコンで動いている Claude（あなた）に向けたものです。開発している PC の Claude が書きました。

利用者は「3D Theater」という、MMD のキャラクターを動かすアプリを作っています。あなたには、このノートパソコンで確かめ用の zip を動かしてほしいです。
確かめたら、結果を受け渡しのフォルダーに置いてください。

今回の zip で見たいのは、次の 2 つです。

- 「1」: **ARM64 の版が動くか、速さがどう変わるか**（先にする）。
  - このノートパソコンの CPU は ARM64 です。今までの zip は x64 の版で、Windows が x64 をまねて動かしていました（ログの CPU の行が「ARM64（x64 の版を、まねて動かしている）」）。
  - 今回の zip（名前に「ARM64」が入っている）は、まねずにそのまま動く版です。C++ の部品・顔のトラッキング（ONNX Runtime）・.NET も ARM64 のものにしました。
  - 開発している PC は x64 なので、ARM64 の版を一度も動かせていません。起動するか・トラッキングと描画が動くか・速さと CPU の重さがどう変わるかを見ます。
- 「1-2」: **タッチパッドで回る速さは、どれくらいがちょうどよいか**（「1」の後）。
  - 前回（zip 20261117-1954）の「1-3」で、描画を軽くした版は、このノートパソコンでも 60 回/秒近くで描けるようになりました（GPU の時間 8.6〜21.6 ms → 0.7〜4.0 ms）。利用者も「なめらかになった」と答えました。
  - 前々回、タッチパッドの回る速さを聞いたときは、描画が遅くて「滑らかではない」という答えで、速さそのものは見てもらえませんでした。描画が速くなったので、今回もう一度見てもらいます。
  - 設定画面の「操作」に「回る速さ」のつまみ（0.25〜3 倍。初めは 1 倍）を足しました。利用者に、指で回しながら、ちょうどよい速さを選んでもらいます。選んだ速さは、このノートパソコンの設定として覚えます。
アプリは、1 分ごとに速さと重さをログに書きます。「1」では、あなたがコマンドでアプリを起動し、ログを読みます。「1-2」では、利用者がタッチパッドで画面を操作します（あなたは画面を操作しない・撮らない。アプリを起動して、答えをメモに残す）。

## 守ってほしいこと

- 利用者とのやり取りは、すべて日本語で、専門用語を使わずに書く。
- 始める前に、流れを利用者に伝えて、よいか聞く。
  - 全部で 30 分ほどかかる。今回するのは「1」と「1-2」。
  - 利用者には、コンセントにつないでもらう。「1」のはじめの 2 分は、カメラの前に座ってもらう。そのあとの 5 分は、ノートパソコンを触らずに置いてもらう。
    「1-2」では、タッチパッドで回したり、設定を変えたりしてもらう（カメラの前に座らなくてよい）。あなたは、答えをメモに残す。
  - 前回の「1-3」（描画の速さ）と、前回までの「2. 前の確かめ」は、利用者に頼まれたときだけする。
- アプリと Windows の設定を、勝手に変えない（カメラの使用の許可・電源モードなど）。
  - 変える必要があれば、やり方を伝えて、利用者に頼む。
- 管理者として動かさない（どの手順にも要らない）。
- 仮想カメラ（設定画面の「配信」にある「仮想カメラを使う」）は使わない（入れると、Windows に部品を登録するので、管理者の確認が出る）。
- カメラの映像・写真・画面を撮らない・保存しない。
  - アプリも映像を保存しない（ログには数だけが残る）。
- 結果は、受け渡しのフォルダー（利用者の Dropbox）に置くだけにする。ほかの所（インターネットのサービスなど）には送らない。
- 窓（確認の窓など）が出て止まったら、何と出ているかを利用者に聞き、利用者に押してもらう。
- 分からないことがあれば、推測で進めずに利用者に聞く。
- コマンドは PowerShell で動かす（PowerShell のツールが無ければ `powershell -NoProfile -Command "..."` で）。

## 0. 準備

1. 受け渡しのフォルダー（Dropbox の「開発\3D Theater」）を見つける。

   ```powershell
   $share = Join-Path $env:USERPROFILE 'Dropbox\開発\3D Theater'
   Test-Path $share
   ```

   - 無ければ、ほかのドライブの `Dropbox\開発\3D Theater` を探すか、利用者に場所を聞く。

2. 中の物を見る（`Get-ChildItem $share`）。使うのは次の 3 つ。
   - `3DTheater-確かめ用-0.1.0-ARM64-日付.zip`: アプリ（ARM64 の版）。
     - いくつかあれば、名前の日付と時刻がいちばん新しいものを使う（下のコマンドは、そのように選ぶ）。
     - 名前に「ARM64」の無い zip は、x64 の版（前回までと同じ、まねて動かす版）。今回は、ARM64 の版が起動しなかったときだけ使う（「1」の 7）。
     - 前に展開した `3D Theater` フォルダーは使わない。
   - `YYB式鏡音レン水着ver1.00\YYB式鏡音レン水着v1.00.pmx`: 確かめに使うキャラクターのモデル（前回と同じ）。
   - この指示書。

3. zip を、ノートパソコンの中（Dropbox の外）に展開する（Dropbox の中で動かすと、同期と重なって遅くなることがある）。

   ```powershell
   $zip = Get-ChildItem $share -Filter '3DTheater-確かめ用-*-ARM64-*.zip' | Sort-Object Name | Select-Object -Last 1
   $work = Join-Path $env:LOCALAPPDATA '3DTheater-確かめ'
   if (Test-Path $work) { Remove-Item $work -Recurse -Force }   # 前の確かめで展開した物（この確かめ用の場所だけ）
   New-Item -ItemType Directory -Force $work | Out-Null
   Copy-Item $zip.FullName $work
   $local = Join-Path $work $zip.Name
   Unblock-File $local   # 「インターネットから来た」印を外す（外さないと、展開したアプリの起動が止められることがある）
   Expand-Archive $local $work
   $app = Join-Path $work '3D Theater\3DTheater.exe'
   $pmx = Join-Path $share 'YYB式鏡音レン水着ver1.00\YYB式鏡音レン水着v1.00.pmx'
   $logDir = Join-Path $env:LOCALAPPDATA '3DTheater\Logs'
   "zip: $($zip.Name)・アプリ: $(Test-Path $app)・モデル: $(Test-Path $pmx)"
   ```

4. 今回の分のログを選ぶため、始めた時刻を控えておく。

   ```powershell
   $since = Get-Date
   ```

   - 変数は、コマンドの間で消えることがある。そのときは、上の値を入れ直す。`$since` は、控えた時刻を `Get-Date '2026-11-14 20:00'` の形で入れ直す。
   - ログは 1 日に 1 つのファイルで、アプリが動いている間は、ファイルの更新日時が変わらないことがある（前回見つけてもらった）。
     そのため、ログのコマンドは、ファイルを「その日のもの」（`$since.Date` より後）で選び、行の時刻で `$since` より後に絞る。

## 1. 今回の確かめ（その 1）: ARM64 の版で動かす（コマンドだけ。12 分ほど）

ARM64 の版で、トラッキングを 2 分、描画だけを 75 秒ずつ 3 回動かし、前回までの x64 の版（まねて動かした）の数と比べる。

1. 利用者に頼む。
   - ノートパソコンを、コンセントにつなぐ。電源モードは、前回と同じ「最適なパフォーマンス」のままにしてもらう（比べるため。勝手に変えない）。
   - はじめの 2 分（下の 2）: カメラの前に座り、画面のキャラクターを見ながら、首を振ったり、まばたきしたりする（顔がカメラに写っていればよい）。
   - そのあとの 5 分（下の 3）: ノートパソコンを触らずに置いておく（画面は見ていてよい。窓を動かしたり、大きさを変えたりしない）。
   - 準備ができたら教えてもらう。

2. トラッキングをしながら 2 分動かす。2 分たつと、アプリが自分で閉じる（保存は尋ねない）。
   - コマンドの待ち時間（timeout）を 10 分（600000 ms）にする。

   ```powershell
   $since = Get-Date
   $p = Start-Process $app -ArgumentList @('--live', "`"$pmx`"", '--track-camera="Surface Camera Front"', '--exit-after=120') -PassThru
   if ($p.WaitForExit(300000)) { "閉じました（終了コード $($p.ExitCode)・$([int]((Get-Date) - $since).TotalSeconds) 秒）" } else { '5 分たっても閉じません' }
   ```

   - 「閉じました」の秒が 30 秒より短い・終了コードが 0 でないときは、起動に失敗したかもしれない。4 のコマンドでログを見てから、7 へ。
   - 「5 分たっても閉じません」なら、利用者に画面を見てもらい、出ている言葉を聞く。閉じてよければ、利用者に閉じてもらう（保存は「いいえ」）。
   - 「Surface Camera Front」のカメラが無いと出たら、下の「2-1」の 3 と同じようにする。

3. 描画の速さを測る（トラッキングはしない。3 回続けて、どの回も 75 秒で自分で閉じる。5 分ほど）。前回の「1-3」の 1・3・4 回目と同じ指定。
   - コマンドの待ち時間（timeout）を 10 分（600000 ms）にする。

   ```powershell
   $runs = @(
       @{ Name = 'ふつう・1280x800'; Args = @('--preview-quality=standard', '--window=1280x800') },
       @{ Name = 'ふつう・最大化';   Args = @('--preview-quality=standard', '--window=maximized') },
       @{ Name = '軽い・最大化';     Args = @('--preview-quality=light', '--window=maximized') }
   )
   foreach ($run in $runs) {
       $p = Start-Process $app -ArgumentList (@('--live', "`"$pmx`"") + $run.Args + @('--exit-after=75')) -PassThru
       if ($p.WaitForExit(180000)) { "$($run.Name): 閉じました（終了コード $($p.ExitCode)）" } else { "$($run.Name): 3 分たっても閉じません"; break }
       Start-Sleep -Seconds 5
   }
   ```

4. ログの、大事な行を見る。

   ```powershell
   Get-ChildItem $logDir -Filter '*.log' | Where-Object { $_.LastWriteTime -ge $since.Date } |
       ForEach-Object { Get-Content $_.FullName -Encoding UTF8 } |
       Where-Object { $_ -match '^\d{4}-\d\d-\d\d \d\d:\d\d:\d\d' -and [datetime]::ParseExact($_.Substring(0, 19), 'yyyy-MM-dd HH:mm:ss', $null) -ge $since } |
       Where-Object { $_ -match '\] CPU: |確かめのため|拡大率|トラッキングを始めます|\[(速さ|重さ|まとめ)\]|\[(ERROR|WARN )\]' }
   ```

   - CPU の行が「CPU: ARM64・論理 CPU 12 個」（「まねて」が無い）なら、ARM64 の版で動いている。
     「ARM64（x64 の版を、まねて動かしている）」と出たら、x64 の版を起動している（0 の 2・3 で選んだ zip の名前を確かめる）。
   - 比べる、前回までの数（x64 の版をまねて動かしたとき。どれもコンセント・「最適なパフォーマンス」）:

     | 何を | 前回までの x64 の版 |
     |---|---|
     | トラッキング（zip 20261115-1603。1 分ずつ 3 回） | 29.1〜29.7 回/秒・処理 平均 13.1〜13.3 ms・95% 16.2〜16.5 ms・顔あり 100% |
     | 描画 ふつう・1280x800（zip 20261117-1954） | 56.7 回/秒・1 回 平均 7.4 ms（95% 9.2 ms）・GPU 1.7 ms |
     | 描画 ふつう・最大化 | 58.0 回/秒・1 回 平均 10.9 ms（95% 13.8 ms）・GPU 4.0 ms |
     | 描画 軽い・最大化 | 58.2 回/秒・1 回 平均 11.4 ms（95% 13.0 ms）・GPU 1.0 ms |
     | 描画だけの回の CPU（「[まとめ] ライブモード」の「CPU 平均」） | 5% |
     | 描画だけの回のメモリ（同じく「始め」） | 830〜890 MB |

   - 見たいこと:
     - トラッキングの「処理 平均」と「95%」: まねずに動くので、短くなるはず。
     - 描画の「1 回 平均」（画面の更新 1 回に、アプリが使った時間）: まねる分が無くなるので、短くなるかもしれない。
     - 「GPU」: 同じくらいのはず（GPU の仕事は変わらない）。
     - 「CPU 平均」とメモリ。

5. 利用者に聞いて、答えをそのままメモに残す（短くてよい。分からなければ「分からない」でよい）。
   - キャラクターの見た目（色・影・輪郭線・髪の揺れ）で、前とちがう・おかしいと感じた所はあったか（描き方は変えていないので、同じはず）。
   - 首やまばたきへのキャラクターの付いて来方は、前と比べてどうだったか（同じ・よくなった・悪くなった）。
   - 止まった・おかしな表示が出た・ノートパソコンが熱くなった・ファンの音が大きくなった、などはあったか。

6. 続けて「1-2」へ（同じ ARM64 の版を使う。展開し直さない）。

7. ARM64 の版が起動しなかったとき（起動してすぐ閉じる・エラーの窓が出る）:
   - 出た言葉を利用者に聞き、4 のコマンドで出た行（とくに ERROR）と一緒にメモに写す。3 はしない。
   - 「1-2」は、x64 の版（名前に「ARM64」の無い、いちばん新しい zip）で行う。次のコマンドで zip を選び直し、0 の 3 のコマンドの 2 行目から（`$work = ...` から）もう一度動かして展開する。

     ```powershell
     $zip = Get-ChildItem $share -Filter '3DTheater-確かめ用-*.zip' | Where-Object { $_.Name -notmatch 'ARM64' } | Sort-Object LastWriteTime | Select-Object -Last 1
     ```

## 1-1. 前の確かめ（頼まれたときだけ）: 1 分ずつ 3 回（閉じるときに、すぐ止まるか）

1. 利用者に頼む。
   - ノートパソコンを、コンセントにつなぐ。
   - カメラの前に座り、画面のキャラクターを見ながら、首を振ったり、まばたきしたりする（細かい動きは要らない。顔がカメラに写っていればよい）。
   - アプリが 3 回続けて起動して、1 分ずつで自分で閉じる（4 分ほど）。
   - 準備ができたら教えてもらう。

2. 3 回続けて起動する。どの回も、1 分たつとアプリが自分で閉じる（保存は尋ねない）。
   - このコマンドは 4 分ほどかかる。コマンドの待ち時間（timeout）を 10 分（600000 ms）にする。

   ```powershell
   foreach ($i in 1..3) {
       $p = Start-Process $app -ArgumentList @('--live', "`"$pmx`"", '--track-camera="Surface Camera Front"', '--exit-after=60') -PassThru
       if ($p.WaitForExit(180000)) { "$i 回目: 閉じました（終了コード $($p.ExitCode)）" } else { "$i 回目: 3 分たっても閉じません"; break }
       Start-Sleep -Seconds 5
   }
   ```

   - 「3 分たっても閉じません」と出たら、利用者に画面を見てもらい、出ている言葉を聞く（下の「2-1」の 2 と同じ）。

3. ログの、閉じるときの行を見る。

   ```powershell
   $lines = @(Get-ChildItem $logDir -Filter '*.log' | Where-Object { $_.LastWriteTime -ge $since.Date } |
       ForEach-Object { Get-Content $_.FullName -Encoding UTF8 } |
       Where-Object { $_ -match '^\d{4}-\d\d-\d\d \d\d:\d\d:\d\d\.\d{3}' -and [datetime]::ParseExact($_.Substring(0, 19), 'yyyy-MM-dd HH:mm:ss', $null) -ge $since })
   $lines | Where-Object { $_ -match 'トラッキングを始めます|たったので閉じます|\[まとめ\] 顔のトラッキング|止まりません|止めるのに|閉じるのに|終了します|\[(ERROR|WARN )\]' }
   $closing = $null
   foreach ($l in $lines) {
       $t = [datetime]::ParseExact($l.Substring(0, 23), 'yyyy-MM-dd HH:mm:ss.fff', $null)
       if ($l -match 'たったので閉じます') { $closing = $t }
       elseif ($l -match '終了します' -and $closing) { '閉じるのにかかった時間: {0:F1} 秒' -f ($t - $closing).TotalSeconds; $closing = $null }
   }
   ```

   - 直っていれば、どの回も次のようになる。
     - 「顔のトラッキングのスレッドが 5 秒で止まりません（…）」の警告が無い。
     - 「[まとめ] 顔のトラッキング」の行が、1 回に 1 つある。
     - 閉じるのにかかった時間が、1 秒ほど（前回は、止まらなかった回で 5.3 秒ほど）。
   - 「カメラが無い」「顔あり」が低いときは、下の「2-1」の 3 と同じようにする。

4. 利用者に聞いて、答えをそのままメモに残す: 3 回の間に、止まった・閉じなかった・おかしな表示が出た、などはあったか。

## 1-2. 今回の確かめ（その 2）: タッチパッドで回る速さを選ぶ（15 分ほど）

マウスの無いノートパソコンでも、タッチパッドの 2 本指で視点を動かせるようにしました。開発している PC にはタッチパッドが無いので、本物の指での使い心地を、利用者に試してもらいます。
ここだけは、利用者が画面を操作します。あなたは、アプリを起動して、利用者の答えをメモに残します（画面は操作しない・撮らない）。

1. アプリを起動する（トラッキングはしない。利用者が閉じるまで動く）。

   ```powershell
   $p = Start-Process $app -ArgumentList @('--live', "`"$pmx`"") -PassThru
   "プロセスの番号: $($p.Id)"
   ```

2. 利用者に、次を順に試してもらう（展開したフォルダーの `確かめの手順.txt` の「（6）」と同じ）。
   - 左のサイドバーの「設定」を押す。出た窓の左の一覧の「操作」で、「タッチパッドで操作する」を入れて、設定の窓を閉じる。
   - プレビュー（キャラクターが映っている所）の上で、2 本指で上下・左右になでる → キャラクターの周りを回るか。
   - 指を広げる・つまむ → キャラクターに近づく・離れるか。
   - Shift を押しながら 2 本指でなでる → 向きを変えずに、上下左右にずれるか。
   - 左のサイドバーの上で 2 本指でなでる → カメラは動かないか（サイドバーの中身が長ければ、サイドバーが上下に動く）。
   - Ctrl＋Z → 直前の 1 回ぶんの、なでる・つまむが戻るか。
   - 回る向きが思ったのと逆なら、「設定」→「操作」の「2 本指でなでたときの向きを逆にする」を入れて、もう一度なでてもらう。
   - **回る速さを選ぶ（今回いちばん見たいこと）**: まず「回る速さ」が 1.00 倍のまま、2 本指で左右・上下になでて、速すぎる・遅すぎるを感じてもらう。
     次に、設定の窓を開いたまま（プレビューが見える所に置く）、「操作」の「回る速さ」のつまみを動かして、なでては変え、ちょうどよい速さを選んでもらう。
     つまみの右に「1.50 倍」のように出る。選んだら、設定の窓を閉じる（選んだ速さは覚える）。

3. 利用者に聞いて、答えをそのままメモに残す（短くてよい。分からなければ「分からない」でよい）。
   - 1.00 倍の回る速さ: 速すぎる・遅すぎる・ちょうどよい。
   - 選んだ回る速さ（「○.○○ 倍」。つまみの右に出ている数）と、選んだ理由（例: 「キャラクターの周りを 1 回なでて半周くらいがよい」）。
   - 初めの速さを、選んだ速さに変えたほうがよいと思うか（ほかの人が初めて使うときのため）。
   - 回る向き: 思った向きだったか。「逆にする」を入れたほうがよかったか。
   - 近づく・離れる: 量と速さはちょうどよいか。
   - ずらす（Shift）: 速さはちょうどよいか。
   - サイドバーの上でなでたとき: カメラが動いてしまわなかったか。
   - 見にくい所: どの画面の、どこか。
   - ほかに気づいたこと・使いにくいこと。

4. 利用者に、アプリを閉じてもらう（保存を尋ねられたら「いいえ」）。閉じたと言われたら、確かめる（`<番号>` は 1 で出た番号）。

   ```powershell
   if (Get-Process -Id <番号> -ErrorAction SilentlyContinue) { 'まだ動いています' } else { '閉じました' }
   ```

5. 選んだ回る速さを、設定のファイルで確かめる（閉じた後）。

   ```powershell
   $settings = Get-Content (Join-Path $env:APPDATA '3DTheater\UserSettings\settings.json') -Raw | ConvertFrom-Json
   "タッチパッド: $($settings.LiveTouchpad)・逆: $($settings.LiveTouchpadReverse)・回る速さ: $($settings.LiveTouchpadOrbitSpeed)"
   ```

## 1-3. 前回の確かめ（その 3。頼まれたときだけ）: 軽くした描画の速さを測る（コマンドだけ。9 分ほど）

トラッキングはしない（カメラは使わない）。アプリを 6 回続けて起動し、どの回も 75 秒で自分で閉じる。
回ごとに、プレビューの品質と窓の大きさとカメラの近さを変える（起動の指定で、その回だけ変える。アプリの設定には残らない）。

1. 利用者に頼む。
   - ノートパソコンを、コンセントにつなぐ。
   - 6 回の間（9 分ほど）、ノートパソコンを触らずに置いておく（画面は見ていてよい。窓を動かしたり、大きさを変えたりしない）。
   - 終わったら、見た目となめらかさについて聞く（下の 4）。
   - 準備ができたら教えてもらう。

2. 6 回続けて起動する。
   - このコマンドは 9 分ほどかかる。コマンドの待ち時間（timeout）を 10 分（600000 ms）にする。

   ```powershell
   $since = Get-Date
   $runs = @(
       @{ Name = 'ふつう・1280x800'; Args = @('--preview-quality=standard', '--window=1280x800') },
       @{ Name = '軽い・1280x800';   Args = @('--preview-quality=light', '--window=1280x800') },
       @{ Name = 'ふつう・最大化';   Args = @('--preview-quality=standard', '--window=maximized') },
       @{ Name = '軽い・最大化';     Args = @('--preview-quality=light', '--window=maximized') },
       @{ Name = 'ふつう・1280x800・近く'; Args = @('--preview-quality=standard', '--window=1280x800', '--camera-distance=15') },
       @{ Name = 'ふつう・最大化・近く';   Args = @('--preview-quality=standard', '--window=maximized', '--camera-distance=15') }
   )
   foreach ($run in $runs) {
       $p = Start-Process $app -ArgumentList (@('--live', "`"$pmx`"") + $run.Args + @('--exit-after=75')) -PassThru
       if ($p.WaitForExit(180000)) { "$($run.Name): 閉じました（終了コード $($p.ExitCode)）" } else { "$($run.Name): 3 分たっても閉じません"; break }
       Start-Sleep -Seconds 5
   }
   ```

   - `--preview-quality=`: プレビューの品質（standard = ふつう・light = 軽い）。「軽い」は、線のギザギザを消す処理（なめらかさ）をしない。
   - `--window=`: 窓の大きさ（1280x800 は拡大率 100% のときの大きさ。拡大率 150% なら、画面の上では 1920 × 1200 ほど）か、最大化。
   - `--camera-distance=15`: カメラを、キャラクターの近く（注視点まで 15）へ寄せる。キャラクターが画面いっぱいに写り、いちばん重い。
   - どの回も、1 分たったところで「[速さ] 1 分」の行を書き、閉じるときに残りの十数秒の分の行を書く。
   - 「3 分たっても閉じません」と出たら、利用者に画面を見てもらい、出ている言葉を聞く。

3. ログの、大事な行を見る。

   ```powershell
   Get-ChildItem $logDir -Filter '*.log' | Where-Object { $_.LastWriteTime -ge $since.Date } |
       ForEach-Object { Get-Content $_.FullName -Encoding UTF8 } |
       Where-Object { $_ -match '^\d{4}-\d\d-\d\d \d\d:\d\d:\d\d' -and [datetime]::ParseExact($_.Substring(0, 19), 'yyyy-MM-dd HH:mm:ss', $null) -ge $since } |
       Where-Object { $_ -match '確かめのため|拡大率|\[速さ\]|\[(ERROR|WARN )\]' }
   ```

   - どの回も、「確かめのため、プレビューの品質を…」「確かめのため、窓を…」の行のあとに、「[速さ] 1 分」の行がある。近くの 2 回は、「確かめのため、「ライブカメラ」の注視点までの距離を 15 にします」の行もある。
   - 「[速さ]」の行の読み方:
     - 「描く大きさ 1896 × 1140（なめらかさ 4 倍）」: プレビューを何画素で描いたか（1 分の間に、いちばん多く描いた大きさ）。「軽い」なら「なめらかさ なし」。
     - 「GPU 22.0 ms（影 0.4・場面 17.0・重ね 0.1・まとめ 4.3）」: 1 回描くのに GPU が掛けた時間と、その内訳。
       影 = 影の下準備、場面 = 背景・床・キャラクター、効果 = 映像効果（使ったときだけ出る）、重ね = 線など、まとめ = なめらかさの点を 1 画素にまとめる。
   - 6 回の「描く大きさ」が、窓の大きさに合っていなければ（全部同じ大きさなど）、そのことをメモに書く。

4. 利用者に聞いて、答えをそのままメモに残す（短くてよい。分からなければ「分からない」でよい）。
   - 前回（なめらかではない、と感じたとき）と比べて、キャラクターの揺れ（髪など）のなめらかさは変わったか。
   - キャラクターの見た目（色・影・輪郭線）で、前とちがう・おかしいと感じた所はあったか（描き方は変えていないので、同じはず）。
   - 6 回の間に、止まった・おかしな表示が出た、などはあったか。

## 数の見方（ログの「[速さ]」「[重さ]」「[まとめ]」）

- トラッキング ○ 回/秒: カメラの速さ（ふつう 30）に近ければよい。
- 処理 平均 ○ ms: 1 枚の顔の読み取りの時間。
  - 33 ms より短ければ、1 秒に 30 回に間に合う。
  - 95% の値・最大が、ときどき大きいのは、かくつきの元。
- 映像待ち 平均 ○ ms: カメラの次の絵を待った時間。0 に近いと、読み取りがカメラに追いついていない（遅れが増える）。
- 顔あり ○%: 顔を見つけた割合。90% 以上がよい。
- 探し直し ○ 回: 顔を見失って、探し直した回数。
- 描画 ○ 回/秒: 画面の更新の回数（ノートパソコンの画面なら 60 や 120 など）に近ければよい。
- GPU ○ ms（影・場面・効果・重ね・まとめ）: 1 回描くのに GPU が掛けた時間と、その内訳。16.7 ms より短ければ、1 秒に 60 回に間に合う。
  どの段が大きいか、品質（なめらかさ）と窓の大きさで、どの段がどれだけ変わるかを見たい。
- 描く大きさ ○ × ○（なめらかさ ○ 倍）: プレビューを描いた画素の数と、1 画素あたりの点の数。
- つかえ ○ 回: 画面の更新が 50 ms 以上止まった回数。少ないほどよい。
  - 起動した直後の 1 分は、モデルの読み込みで何回かある。
- CPU ○%（PC 全体のうち）: このアプリが、CPU 全体のどれだけを使ったか。
- メモリ ○ MB: 1 分ごとに数十 MB 上下するのは、ふつうのこと。まとめの「最小」「最大」で上下の幅が分かる。
  - 「増え方 ○ MB/時」は、22 分より長く動かしたときだけ出る（5 分では「増え方は、22 分ほど動かすと分かる」と出る）。
  - 30 分動かして、増え方が 1 時間に 100 MB より大きければ、メモリが漏れているかもしれない。
  - 前々回、Windows が「メモリが増え続けているかもしれない」と記録したので、ここを見たい。
- 「顔のトラッキングのスレッドが 5 秒で止まりません（…）」の警告は、この版では出ないはず。出たら、かっこの中（そのとき何をしていたか）をメモに写す。
  「顔のトラッキングを止めるのに ○ 秒かかりました」「カメラを閉じるのに ○ 秒かかりました」の行も写す。
- 電源: 「電池 ○%」か「コンセント」か・省エネ機能・電源モード。
  - まとめに「→」があれば、始めと終わりで違った（電池の減り方が分かる）。

## 困ったとき

- アプリが起動しない・すぐ閉じる: ログの ERROR の行と、`collect-logs.ps1` が集める Windows の記録を、メモに書く。
- 「Windows によって PC が保護されました」と出た:
  - `Unblock-File` を忘れていないか確かめる。
  - 利用者に「詳細情報」→「実行」を押してもらってもよい。
- カメラを開けない（ログの ERROR に「カメラ」とある）:
  - ほかのアプリ（Teams・カメラのアプリなど）がカメラを使っていないか、利用者に確かめてもらう。
  - Windows の設定 →「プライバシーとセキュリティ」→「カメラ」で、「デスクトップ アプリがカメラにアクセスできるようにする」がオンかを、利用者に見てもらう（勝手に変えない）。
