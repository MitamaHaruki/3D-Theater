# プラグインの作り方

3D Theater に機能を足すプラグイン（C# の DLL）の作り方。SDK の版は **1.5**（前の版との違いは「版の決まり」）。
決めたことと理由は [設計判断記録](設計判断記録.md) の 39 章（土台）・40 章（編集）・41 章（ツールバー・右クリックのメニュー・状態表示）・42 章（時間のかかる処理とファイルの形式）・43 章（描画の SDK・連携・API 文書）・44 章（編集の道具）にある。見本は `plugins/3DTheater.SamplePlugin`（サンプル: シーンの情報）。

> プラグインはアプリと同じプロセスで動き、パソコンのファイルなどにも触れられる。アプリは、初めて見つけたプラグインを無効にしておき、利用者が「プラグインの管理」で確かめて有効にする。

## 今できること

| できること | 使うもの | plugin.json の requires |
|---|---|---|
| メニューのコマンドとショートカット | `context.Commands`（`ICommandRegistry`） | `commands` |
| プラグインごとの設定を覚える | `context.Settings`（`IPluginSettings`） | `settings` |
| アプリのログに書く | `context.Log`（`IPluginLog`） | （要らない） |
| 時間のかかる処理（進み具合の窓と「取り消す」） | `context.GetService<IPluginTasks>()` | `tasks` |
| ファイルの形式（ファイルのメニュー・ドラッグでの読み込み・書き出し） | `context.GetService<IFileFormatRegistry>()` | `files` |
| ドッキングパネル | `context.GetService<IPanelRegistry>()` | `panels` |
| メッセージを出す・自分の窓の持ち主を知る | `context.GetService<IPluginUi>()` | `ui.dialogs` |
| ツールバーのボタン（コマンドを実行する） | `context.GetService<IToolbarRegistry>()` | `ui.toolbar` |
| 右クリックのメニューの項目（コマンドを実行する） | `context.GetService<IContextMenuRegistry>()` | `ui.contextmenu` |
| 状態表示（ウィンドウのいちばん下）の文字の欄 | `context.GetService<IStatusBarRegistry>()` | `ui.statusbar` |
| 編集の道具（プレビューの左ボタンのドラッグを受け取る） | `context.GetService<IEditToolRegistry>()` | `ui.edittools` |
| シーン・再生位置・選択を読み、変化を知る | `context.GetService<ITheaterScene>()` | `scene.read` |
| ボーン・モーフの名前・今の値・キーを読み、編集の知らせを受ける | `ITheaterScene`（`GetBonePose`・`GetMorphKeys`・`Edited` など） | `scene.read` |
| ボーン・モーフの値とキーを変える（アプリの「元に戻す」1 回分にまとめる） | `context.GetService<ITheaterEditor>()` | `scene.edit` |
| 再生位置を動かす | `ITheaterScene.SeekFrame` | `scene.seek` |
| シーンを書き出しと同じ描き方で絵にする（画素と PNG） | `context.GetService<ITheaterRenderer>()` | `render.image` |

- requires に書いた機能がアプリに 1 つでも無いと、読み込む前に「このアプリでは使えません」になる（権限ではなく、互換性の確かめに使う）。
- カメラ・照明などの編集、キーの補間、道具がプレビューに線や印を描くことなどは、後の版で足す。

## 1. プロジェクトを作る

.NET 10 のクラスライブラリにする。パネルを使うなら WPF を使う。

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <!-- プラグインとして読み込まれる DLL にする（使う NuGet の DLL も出力に集まる） -->
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <!-- 3D Theater の入ったフォルダー -->
    <TheaterDir>C:\Apps\3DTheater</TheaterDir>
  </PropertyGroup>

  <!-- 契約の DLL はアプリのものを使う。プラグインの出力には写さない（Private=false） -->
  <ItemGroup>
    <Reference Include="Plugin.Core" HintPath="$(TheaterDir)\Plugin.Core.dll" Private="false" />
    <Reference Include="Plugin.UI.Wpf" HintPath="$(TheaterDir)\Plugin.UI.Wpf.dll" Private="false" />
    <Reference Include="3DTheater.Plugin.SDK" HintPath="$(TheaterDir)\3DTheater.Plugin.SDK.dll" Private="false" />
  </ItemGroup>

</Project>
```

| DLL | 中身 |
|---|---|
| `Plugin.Core` | 入口（`IPlugin`）、`IPluginContext`、コマンド・設定・ログ。アプリに依存しない共通の契約 |
| `Plugin.UI.Wpf` | パネル・メッセージ・配色の資源の名前（WPF） |
| `3DTheater.Plugin.SDK` | 3D Theater 専用の機能（シーン）と、host と SDK の版 |

契約の DLL をプラグインのフォルダーに置いても読まれない（アプリが読んだものを使う）。

契約の DLL の隣には、説明の XML（`Plugin.Core.xml` など）がある。上のように参照すると、Visual Studio の候補に日本語の説明が出る（API 文書）。

## 2. plugin.json を書く

DLL と同じフォルダーに置く。コメント（`//`）と最後のカンマは書いてよい。

```json
{
  "id": "example.scene-info",
  "name": "シーンの情報",
  "version": "1.0.0",
  "host": "3DTheater",
  "sdkVersion": "1.5",
  "assembly": "Example.SceneInfo.dll",
  "entryType": "Example.SceneInfo.SceneInfoPlugin",
  "description": "今のフレームを知らせます。",
  "author": "作った人",
  "requires": ["commands", "scene.read"]
}
```

| 項目 | 要るか | 意味 |
|---|---|---|
| `id` | 要る | ほかと重ならない名前。英数字と `.` `_` `-` だけ（例: `作者.機能`）。設定とレイアウトの保存に使うので、後から変えない |
| `name` | 要る | 管理画面とメニューに出す名前 |
| `version` | 要る | プラグインの版（`1.0.0` の形） |
| `host` | 要る | `3DTheater` |
| `sdkVersion` | 要る | 作ったときの SDK の版（今は `1.5`。前の版にある機能だけを使うなら、その版にすると古いアプリでも使える） |
| `assembly` | 要る | 入口の DLL（このフォルダーの中。`lib/Example.dll` のような下のフォルダーも可） |
| `entryType` | 要る | 入口の型の名前（名前空間を含む） |
| `description` | なくてよい | 管理画面に出す説明 |
| `author` | なくてよい | 作者 |
| `requires` | なくてよい | 使う機能の名前の並び（上の表） |

**版の決まり**: SDK の版は「主.副」。主の版が違うと使えない。副の版は、アプリの版以下なら使える（SDK 1.0 で作ったものは 1.5 のアプリでも使える。1.5 で作ったものは 1.4 のアプリでは使えない）。

| 版 | 足したもの |
|---|---|
| 1.0 | 入口・コマンド・設定・ログ・パネル・メッセージ・シーンを読む・再生位置を動かす |
| 1.1 | ボーン・モーフの名前・値・キーを読む、編集の知らせ（`Edited`）、選んでいるモデル（`SelectedModelId`）、モデルの Id（`ModelInfo.Id`）、編集（`ITheaterEditor`・`scene.edit`） |
| 1.2 | ツールバーのボタン（`ui.toolbar`）・右クリックのメニューの項目（`ui.contextmenu`・`TheaterMenuPlaces`）・状態表示の欄（`ui.statusbar`） |
| 1.3 | 時間のかかる処理（`IPluginTasks`・`tasks`）・ファイルの形式（`IFileFormatRegistry`・`files`） |
| 1.4 | シーンを絵にする（`ITheaterRenderer`・`render.image`） |
| 1.5 | 編集の道具（`IEditToolRegistry`・`ui.edittools`）と、その区画の情報（`ITheaterView`） |

## 3. 入口の型を書く

`IPlugin` を実装し、引数なしで作れる型にする。

```csharp
using Plugin.Core;
using Plugin.UI.Wpf;
using Theater3D.Plugin.Sdk;

namespace Example.SceneInfo;

public sealed class SceneInfoPlugin : IPlugin
{
    public void Initialize(IPluginContext context)
    {
        ITheaterScene scene = context.GetService<ITheaterScene>()!;
        IPluginUi? ui = context.GetService<IPluginUi>();

        context.Commands.Register(new PluginCommand
        {
            Id = "show-frame",
            Title = "今のフレームを知らせる",
            Shortcut = "Ctrl+Alt+I",
            Execute = () => ui?.ShowMessage($"今のフレームは {scene.CurrentFrame} です。"),
        });
        context.Log.Info("始めました");
    }

    public void Shutdown()
    {
        // 自分で作った窓を閉じる・自分で付けたイベントを外すなど
    }
}
```

- `Initialize` は有効にしたとき（起動時と、管理画面で有効にしたとき）、`Shutdown` は無効にしたときとアプリの終了時に呼ぶ。
- 登録したコマンド・パネルと、`ITheaterScene` のイベントは、`Shutdown` の後にアプリが外す。自分で作った窓やタイマーなどは `Shutdown` で片付ける。
- どちらも画面のスレッドから呼ぶ。コマンドの処理・パネルの中身を作る処理・イベントも画面のスレッドで呼ぶ。別のスレッドで処理したら、画面に触る前に `Dispatcher` で戻す。

## 4. 使える機能

### コマンド（`PluginCommand`）

| 項目 | 意味 |
|---|---|
| `Id`（要る） | プラグインの中で一意の名前 |
| `Title`（要る） | メニューに出す名前 |
| `Execute`（要る） | 実行する処理 |
| `CanExecute` | 今実行できるか（メニューを開いたときに確かめる。無ければいつでも） |
| `Shortcut` | ショートカット（例: `Ctrl+Alt+I`）。Ctrl か Alt を含める |
| `Description` | メニューのヒントに出す説明 |

- メニュー「プラグイン」の、プラグインの名前の項目の下に並ぶ。
- ショートカットは、アプリが使っていないキーだけが届く（アプリのキーが先）。ほかのプラグインが先に使っているショートカットは付かない（問題の記録に残る）。
- `Register` の返す物を `Dispose` すると、そのコマンドだけ外せる。

### 設定（`IPluginSettings`）

- `Get(キー)` / `Set(キー, 値)`。値は文字列（`null` で消す）。数などは自分で文字にする（`CultureInfo.InvariantCulture` を使う）。
- 利用者の設定（`%APPDATA%\3DTheater\UserSettings\settings.json`）に、アプリを閉じるときに一緒に保存する。プロジェクトには入らない。

### パネル（`IPanelRegistry` と `PluginPanel`）

| 項目 | 意味 |
|---|---|
| `Id`（要る） | プラグインの中で一意の名前（レイアウトの保存に使う） |
| `Title`（要る） | タブに出す名前 |
| `CreateContent`（要る） | 中身（`FrameworkElement`）を作る。初めて出すときに 1 度だけ呼ぶ |
| `Placement` | 初めて出す場所（`Right`・`Left`・`Bottom`）。前回のレイアウトがあればそちら |

- アプリのパネルと同じく、タブにする・切り離す・隠す・表示のメニュー「パネル」から出す・レイアウトの保存と復元ができる。
- 色はアプリの暗い配色に合わせる: `block.SetResourceReference(TextBlock.ForegroundProperty, ThemeKeys.Text)` のように、`ThemeKeys`（`Text`・`SubText`・`Panel`・`Border`・`Accent`）を使う。

### 描画（`ITheaterRenderer`）

```csharp
ITheaterRenderer renderer = context.GetService<ITheaterRenderer>()!;
(int width, int height) = renderer.ExportSize;   // 利用者が書き出しの画面で決めた大きさ
RenderedImage image = renderer.RenderFrame(new RenderRequest { Width = width, Height = height, Transparent = true });
File.WriteAllBytes(path, image.Png);              // 透過 PNG
```

| 項目 | 意味 |
|---|---|
| `RenderRequest.Width` / `Height` | 大きさ（1〜8192。初期値 1920 x 1080） |
| `RenderRequest.Frame` | 描くフレーム（null なら今のフレーム） |
| `RenderRequest.Transparent` / `Background` | 背景を透明にするか / 透明にしないときの色（R・G・B を 0〜1。初期値は白） |
| `RenderRequest.Smooth` | 2 倍の大きさで描いて縮める（初期値 true） |
| `RenderedImage.Pixels` | 画素（B・G・R・A。上の行から。透明度は色にかけ合わせていない値） |
| `RenderedImage.Png` | PNG にした中身 |

- 書き出しと同じ描き方（書き出しの品質・映像効果・物理の焼き込み。格子・ボーン・ギズモは映らない。モーションブラーはかけない）。
- 画面のスレッドから呼ぶ。描き終えるまで画面は止まる。描き終えると、再生位置などは元に戻る。
- 時間のかかる処理（`IPluginTasks`）の中で描くと、終わったときに状態表示に知らせが出る。
- ほかのアプリへ渡すときの見本は、サンプルの「今のフレームを画像としてコピー」（`FrameClipboard.cs`。透過 PNG と、白い背景の画像の 2 つの形でクリップボードへ）。

### 編集の道具（`IEditToolRegistry`）

```csharp
context.GetService<IEditToolRegistry>()?.Register(new PluginEditTool
{
    Id = "center-drag",
    Title = "センターを床の上で動かす",     // ボタンの説明と「元に戻す」の名前
    Glyph = "\uE707",
    Activate = () => new CenterDragTool(scene), // 道具を選んだときに、受け取り手を作る
});

sealed class CenterDragTool(ITheaterScene scene) : IEditToolHandler
{
    public bool Pressed(EditToolPointer pointer)
    {
        ITheaterView? view = pointer.GetView<ITheaterView>();   // 視線・ドラッグの編集
        return view?.DragEdit is not null && scene.SelectedModelId is not null; // false ならアプリの操作（選ぶ）に任せる
    }
    public void Moved(EditToolPointer pointer)
    {
        ITheaterView view = pointer.GetView<ITheaterView>()!;
        view.DragEdit!.SetBonePose(...);                         // ドラッグ 1 回の編集は、放すと 1 つの「元に戻す」になる
    }
    public void Released(EditToolPointer pointer) { }
    public void Cancelled() { }                                 // Esc・右クリック（編集はアプリが元に戻してから呼ぶ）
    public void Deactivated() { }                               // ほかの道具を選んだ・無効にした
}
```

| 項目 | 意味 |
|---|---|
| `EditToolPointer.Position` / `ViewSize` / `Modifiers` | 区画の左上からの位置・区画の大きさ（WPF の画面の単位）・押していた Ctrl・Shift・Alt |
| `ITheaterView.RayOrigin` / `RayDirection` | マウスの位置を通る視線（ワールドの座標。クリックで選ぶときと同じ） |
| `ITheaterView.Project(点)` | ワールドの点が区画のどこに見えるか（視点の後ろなら null） |
| `ITheaterView.DragEdit` | ドラッグの編集（押してから放すまで。`Pressed` の中からも使える）。使うには requires に `scene.edit` |

- 道具はツールバーに押したままになるボタンで並ぶ。選んでいる間は、プレビューの左ボタンの操作が道具に渡り、ギズモは出ない。視点の操作（中ボタン・ホイール）と右クリックのメニューはアプリのまま。
- ドラッグ 1 回の編集はアプリがまとめる。放すと 1 つの「元に戻す」に、Esc・ドラッグ中の右クリック・`Pressed` が false のときは元に戻る。ドラッグの途中は、元に戻す・やり直しは効かない。
- アプリの道具のボタン・Q / W / E・ギズモの方式を選ぶと、プラグインの道具は外れる。

### ツールバー・右クリックのメニュー・状態表示

```csharp
// ボタンとメニューの項目は、先に登録したコマンドを Id で指す（名前・説明・使えるか・処理はコマンドのもの）
context.GetService<IToolbarRegistry>()?.Register(new PluginToolbarButton { CommandId = "show-frame", Glyph = "\uE890" });
context.GetService<IContextMenuRegistry>()?.Register(new PluginContextMenuItem { CommandId = "show-frame", Place = TheaterMenuPlaces.Preview });

// 状態表示の欄。文字を変えると表示が変わる
IStatusBarItem? time = context.GetService<IStatusBarRegistry>()?.Add("time");
if (time is not null)
{
    scene.FrameChanged += (_, _) => time.Text = $"フレーム {scene.CurrentFrame}";
}
```

| 項目 | 意味 |
|---|---|
| `PluginToolbarButton.CommandId`（要る） | 押したときに実行するコマンドの Id（このプラグインが先に登録したもの） |
| `PluginToolbarButton.Glyph` | 絵の文字（Segoe Fluent Icons の 1 文字。アプリのツールバーと同じ字体）。無ければ `Text` |
| `PluginToolbarButton.Text` | ボタンの文字（`Glyph` も無ければコマンドの名前） |
| `PluginContextMenuItem.CommandId`（要る） | 選んだときに実行するコマンドの Id |
| `PluginContextMenuItem.Place`（要る） | 足すメニュー: `TheaterMenuPlaces.Preview`（プレビューの右クリックと視点のボタン）・`TheaterMenuPlaces.SceneTree`（シーンの一覧の行の右クリック） |
| `IStatusBarRegistry.Add(Id)` | 状態表示に欄を足す。返したものの `Text`（空なら隠す）・`ToolTip` を変える。`Dispose` で外す |

- ボタンと項目は、コマンドが今使えないとき（`CanExecute` が false）は押せない。コマンドを外すと、ボタンと項目も外れる。
- ボタンの説明（マウスを乗せたとき）には、コマンドの名前・ショートカット・説明・プラグインの名前が出る。
- シーンの一覧の右クリックでは、右クリックした行を選んでからメニューを出す。コマンドは選んでいる物（`SelectedModelId` など）に対して動かす。

### 時間のかかる処理（`IPluginTasks`）

```csharp
IPluginTasks tasks = context.GetService<IPluginTasks>()!;
PluginTaskResult result = await tasks.RunAsync("数えています", async task =>
{
    for (int i = 1; i <= 50; i++)
    {
        await Task.Delay(100, task.Cancellation);   // 取り消されたら OperationCanceledException で止まる
        task.Report(i / 50.0, $"{i} / 50");          // 進み具合（0〜1。分からなければ null）と、今していること
    }
});
```

- 画面のスレッドから始める。0.3 秒で終わらなければ、題名・進み具合・「取り消す」の窓が出る（その間、アプリの操作はできない）。
- 重い計算やファイルの読み書きは `Task.Run` に分ける。`await` の後は画面のスレッドに戻るので、SDK（シーンを読む・編集する）はそこで使う。
- `task.Report` はどのスレッドから呼んでもよい。何度呼んでも、画面の書き換えはまとめて行う。
- 結果（`PluginTaskResult`）: `Completed`（終わった）・`Cancelled`（取り消された）・`Failed`（例外。アプリがメッセージで知らせ、問題の記録に残す）。`RunAsync` は例外を投げないので、コマンドからは `Execute = () => _ = tasks.RunAsync(...)` のように待たずに始めてよい。

### ファイルの形式（`IFileFormatRegistry`）

```csharp
context.GetService<IFileFormatRegistry>()?.Register(new PluginFileFormat
{
    Id = "key-csv",
    Title = "キーの CSV",
    Extensions = [".csv"],
    CanExport = () => scene.SelectedModelId is not null,
    Export = async (path, task) =>
    {
        var rows = Collect(scene);                                   // SDK は画面のスレッドで
        await Task.Run(() => Write(path, rows, task), task.Cancellation); // ファイルは別のスレッドで
    },
    Import = async (path, task) =>
    {
        var rows = await Task.Run(() => Read(path, task), task.Cancellation);
        editor.Edit("キーの CSV の読み込み", edit => { /* rows を当てはめる */ });
    },
});
```

| 項目 | 意味 |
|---|---|
| `Id`・`Title`・`Extensions`（要る） | プラグインの中で一意の名前・メニューとファイルの窓の名前・拡張子（「.csv」の形） |
| `Import` / `Export` | 読み込む・書き出す（少なくとも一方）。どちらも時間のかかる処理と同じく、進み具合の窓・取り消し・エラーの知らせを通る |
| `CanImport` / `CanExport` | 今読み書きできるか（メニューを開いたときと、ドラッグのときに確かめる） |
| `SuggestExportName` | 書き出しの最初のファイルの名前（拡張子なし） |

- ファイルのメニューの「読み込む（プラグインの形式）」「書き出す（プラグインの形式）」に出る。読み込める形式は、ウィンドウへのドラッグと、起動のときに渡したファイルでも読み込む（アプリの形式のファイルを先に読み込む）。
- **`Export` に渡す場所は一時ファイル**（同じフォルダー・同じ拡張子）。書き終えたらアプリが選ばれた名前に置き換える。途中で失敗・取り消すと、一時ファイルを消し、元のファイルは残る。何も書かないとエラーになる。

### メッセージ（`IPluginUi`）

- `ShowMessage(文, 題名)`: アプリの窓の上にメッセージを出す（題名を省くとプラグインの名前）。
- `Owner`: 自分の窓を出すときの持ち主（`window.Owner = ui.Owner`）。

### シーン（`ITheaterScene`）

| 項目 | 意味 |
|---|---|
| `CurrentFrame` / `EndFrame` / `FrameRate` / `IsPlaying` | 今のフレーム・終わりのフレーム・1 秒のフレームの数・再生中か |
| `Models` | シーンのモデル（`ModelInfo`: 名前・ファイル・見えているか・ボーンの数・モーフの数・Id） |
| `SelectedName` | 選んでいる項目の名前（無ければ null） |
| `SelectedModelId` | 選んでいる項目の属するモデル（モデルそのもの・そのボーン・モーフなど）の Id（無ければ null） |
| `SeekFrame(フレーム)` | 再生位置を動かす（0〜終わりに収める） |
| `GetBoneNames(モデル)` / `GetMorphNames(モデル)` | ボーン・モーフの名前（並び順） |
| `GetBonePose(モデル, ボーン)` / `GetMorphWeight(モデル, モーフ)` | 今の値（無ければ null） |
| `GetBoneKeys(モデル, ボーン)` / `GetMorphKeys(モデル, モーフ)` | キー（フレームの順。フレームと値だけ） |
| `FrameChanged` / `SelectionChanged` / `SceneChanged` | 再生位置・選択・シーンの中身（モデルの追加・削除・名前・表示）が変わった |
| `Edited` | 編集の履歴が変わった（利用者かプラグインが編集した・元に戻した・やり直した・プロジェクトを開いた）。キーや値を読み直すきっかけに使う |

- モデルは `ModelInfo.Id` で指す（名前は重なることがある。Id はアプリを起動し直すと変わるので、設定に覚えない）。ボーン・モーフは名前で指す。
- ボーンの値（`BonePose`）は MMD のボーンの移動・回転と同じ: 初期の位置からの移動と回転（四元数）で、親のボーンから見た向き（VMD の値と同じ）。

### 編集（`ITheaterEditor`）

```csharp
ITheaterEditor editor = context.GetService<ITheaterEditor>()!;
string modelId = scene.SelectedModelId!;
int frame = scene.CurrentFrame;

bool changed = editor.Edit("まばたきを入れる", edit =>
{
    edit.SetMorphKey(modelId, "まばたき", new MorphKeyInfo(frame, 0f));
    edit.SetMorphKey(modelId, "まばたき", new MorphKeyInfo(frame + 3, 1f));
    edit.SetMorphKey(modelId, "まばたき", new MorphKeyInfo(frame + 6, 0f));
});
```

| 項目 | 意味 |
|---|---|
| `SetBonePose` / `SetMorphWeight` | 今の値を変える。利用者が手で変えたときと同じ扱い（自動キーが OFF なら未登録の変更、ON なら今のフレームのキー） |
| `SetBoneKey` / `SetMorphKey` | キーを置く（同じフレームのキーは置き換える）。補間は、同じフレームのキーがあればその動き方を引き継ぎ、無ければ直線。モーフの値は 0〜1 に収める |
| `RemoveBoneKey` / `RemoveMorphKey` | キーを消す（消したら true） |

- `Edit` の中の変更は、まとめて **1 回の「元に戻す」** になる（編集のメニューに「元に戻す: 説明」と出る）。何も変わらなければ履歴に積まず、false を返す。
- 中で例外を投げると、始める前の値とキーに戻してから、その例外がそのまま `Edit` から投げられる（途中までの変更は残らない）。
- モデル・ボーン・モーフが無いとき、利用者がロックしているときは、変えずに false を返す。負のフレーム・数でない値・長さ 0 の回転は例外（その編集ごと取り消す）。
- 再生中なら止めてから始める。`Edit` の中で、もう一度 `Edit` は呼べない。`edit` を外に持ち出して後で使うことはできない。

## 5. 置いて試す

1. ビルドした出力（DLL・`*.deps.json`・使う NuGet の DLL）と `plugin.json` を 1 つのフォルダーにまとめる。
2. そのフォルダーを `%APPDATA%\3DTheater\Plugins\` の下に置く（「プラグインの管理」の「プラグインを入れる場所を開く」で開ける）。
3. アプリを起動し直し、「プラグイン → プラグインの管理...」で選んで「有効にする」。

- 更新・削除は、フォルダーを置き換えて（消して）アプリを起動し直すと反映する。無効にしても、DLL はアプリを起動し直すまで読み込まれたまま（ファイルを上書きできないときは、アプリを閉じてから）。
- うまく動かないときは、管理画面の「状態」と「問題の記録」、アプリのログ（`%LOCALAPPDATA%\3DTheater\Logs\`、行の頭に `[プラグインの名前]`）を見る。
- デバッグするときは、Visual Studio でアプリ（`3DTheater.exe`）を起動するようにして、プラグインのプロジェクトからデバッグを始める。

## 6. 失敗したとき、アプリはどうするか

| 起きたこと | アプリのすること |
|---|---|
| plugin.json が読めない・host や SDK の版が合わない・requires の機能が無い・id が重なる | 読み込まない（管理画面に理由を出す） |
| 入口の型が無い・`IPlugin` でない・引数なしで作れない | 始めない（「有効だが始められません」） |
| `Initialize` で例外 | 途中で登録したものを外し、「有効だが始められません」にする（次の起動でまた試す） |
| コマンドで例外 | メッセージで知らせ、問題の記録に残す（プラグインは動いたまま） |
| パネルの中身を作るときに例外 | パネルに理由を出す |
| シーンのイベントの処理で例外 | 問題の記録に残す |
| 編集の道具で例外 | そのドラッグの編集を元に戻し、問題の記録と状態表示に出す |
| `ITheaterEditor.Edit` の中で例外 | 始める前の値とキーに戻し、例外を投げ直す（コマンドの中なら、上のとおりメッセージで知らせる） |
| 時間のかかる処理・ファイルの読み込み・書き出しで例外 | メッセージで知らせ、問題の記録に残す（書き出しなら、元のファイルを残して一時ファイルを消す） |
| `Initialize` の途中でアプリが落ちた | 次の起動でそのプラグインを無効にして知らせる |
| プラグインのせいで起動できない | 利用者は Shift を押しながら（または `--safe-mode` を付けて）起動すると、プラグインを始めずに起動できる（安全モード） |
